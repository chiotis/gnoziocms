# Changelog

## 0.1.166 — 2026-10-19 — Single templates: lists and starting points
- **A block's list can come from the entry's list.** The ⛓ button on a repeater, such as a block's buttons or cards, binds it to one of the entry's repeaters, such as a book's `buy_links`. A compact table in the settings panel maps each column to a field of the entry's rows, to a fixed value for every row, or leaves it empty. Rows are checked and limited like typed ones. A missing column shows a warning instead of an error.
- **A template built with blocks starts from a sensible page, not an empty one.** Any content type gets a starting template generated from its definition (entry title, fact sheet, text, its own blocks, and blocks for its picture and link lists), also a type added later in `custom/content-types/`. A theme can ship hand-made ones in `single-templates/<type>.yaml`, and the default theme has them for its six types, close to their current pages. **Start again** on the template screen goes back to it.
- A new **Buttons** block holds a row of buttons, for example the buy links of a book. See *Templates built with blocks* in `docs/theming.md`.

## 0.1.165 — 2026-10-19 — Single templates built with blocks
- **A content type's page can be built with blocks.** In Theme → Single Layouts, each type can switch from *The theme's* page to *Built with blocks*. **Edit template** opens the block editor with its settings panel and a live preview of a real entry of the type. **Reset** goes back to the theme's page and keeps the built template for later.
- **Blocks can show the entry's own fields.** A ⛓ button beside a block's field binds it to the entry's title, excerpt, main image or one of the type's fields. Only fields that fit are offered, and a bound value is checked like a typed one. A block can hide itself when its bound field is empty.
- **New blocks for templates:** *Entry title* (today's title area), *Fact sheet* (choose the fields), and *Entry blocks* (the entry's own blocks, where the template places them). *Page content* places the entry's text.
- Templates are kept in the theme settings, with a set for each language like Footer Blocks. An entry's own `template:` still wins, and sites that do not use it see no change. Everything is driven by the content type's definition, so a type added later in `custom/content-types/` gets a built template with no code. A binding to a field that was removed shows a warning in the editor and renders as empty. See *Templates built with blocks* in `docs/theming.md`.

## 0.1.161 — 2026-10-19 — Tests that say what is wrong
- **`tests/run.sh` checks the environment first**: the PHP version and extensions (from `composer.json` and the installer), python3 and curl for the HTTP tests, Node 20 for the JavaScript checks. On a mismatch it prints one line per problem and runs nothing (exit code 3); `GNOZIO_TESTS_SKIP_PREFLIGHT=1` skips the check.
- **No test waits forever**: HTTP tests share a `wait_until` with a deadline, every request has a timeout, and each HTTP test has a time limit (`GNOZIO_TEST_TIMEOUT`, 180 seconds by default). A test that runs out is reported as `TIMEOUT <name>` and the rest carry on.
- **Step-by-step tests stop at the first failed step**: the installer, update and fresh-install flows mark the checks that depended on it as skipped, and the summary counts skipped checks apart from failures. See `tests/README.md`.

## 0.1.159 — 2026-10-18 — A one-file installer
- **`installer.php` installs a new site from the browser.** Set its key, upload it to an empty site folder and open it: it checks the server, downloads the latest release, verifies its size and SHA-256, unpacks it with the updater's safety rules and can start from the demo site. Each step shows its progress, in Greek or English, light or dark.
- It then asks you to point the document root at the site's `public/` folder (with a note for CloudPanel) and waits for your OK. It continues only once it is served from `public/`, removes itself and opens `/admin` to create the first administrator.
- It refuses to run without a key of at least 12 characters, or where a site is already installed. It is published with every release as its own file, next to the package, and is not part of the package. See `update.md`.

## 0.1.153 — 2026-10-18 — Search: faster on large sites
- **Search no longer re-normalizes every entry on every request**: the extracted-text cache also keeps the normalized text. Older cache files are rebuilt automatically.
- **Only the first 10 distinct words of a query count**, so a very long query cannot slow the site down.
- **Signed-in and public searches no longer rewrite the cache in turn.** Deleted entries leave the cache on the next signed-in search.

## 0.1.152 — 2026-10-18 — Search: whole words rank higher
- **A whole word ranks above a word start, and a word start above the middle of a word**: *art* puts “Art gallery” before “Party hall”.
- **Short words such as «ο», «της», "a" or "of" match only whole words** and are no longer highlighted inside longer words. Beside longer words they are optional and only raise an entry's position; a query made only of short words needs all of them.

## 0.1.146 — 2026-10-16 — Public search: content, relevance and results
- **Search finds the content in blocks and declared public fields**, including repeaters and container columns, book authors and ISBNs. Hidden blocks, retired/private fields, technical settings, URLs and form definitions are excluded. Field definitions may opt out with `searchable: false`.
- **Greek matching ignores case, accents and final sigma.** All words in a query must match, in any order and across fields; titles rank above mentions in the body. The original spelling stays in the results. Results belong to the current language, without links to missing translations.
- **A fuller results page:** a result count, relevant excerpts with highlighted words, filters by content type and ten results per page. The title-area settings and header search keep working, with no suggestions while typing. - Search uses the existing parsed-content cache and a disposable cache of extracted text, invalidated by content, schema and version changes. No content migration or new server dependency is needed. The admin's separate search is unchanged. See `docs/search.md`.

## 0.1.145 — 2026-10-16 — PHP 8.5, update checks and CI diagnostics
- **PHP 8.5 or newer is required.** Releases are built and tested on PHP 8.5. The installer checks the package requirement, system checks use the same minimum, and a fresh installation on an older PHP explains what to upgrade before loading the application.
- **A short check after installing an update** asks the login page, home page, one published internal page when available, and the sitemap (including the site's choice to disable it). Each request proves that the expected version answered freshly, bypasses page caching and uses a short timeout. A definite failure puts the previous code back; a timeout, redirect, restricted or stale response leaves an explicit *Unverified* result and the option to roll back. The result lists what was checked. The extended check applies to updates started by this version or later; the first upgrade uses the updater already installed.
- **Pushes and releases remain immediate.** The full test suite runs independently in GitHub Actions, on PHP 8.5 only, with a result summary and full diagnostic logs retained for seven days. A test that exits with an error can no longer pass just because its output says `ALL PASSED`; HTTP setup failures are reported immediately.

## 2026-09-29 — Editor role
- New role **Editor**: writes, edits, publishes, and deletes pages, posts, and projects, and manages media, categories, and tags. It cannot open forms, menus, settings, content types, translations, users, logs, backups, updates, or import/export, and it gets a content-only dashboard without system figures or notifications
- Raw HTML is an administrator privilege: an editor's HTML is shown as plain text (with a notice), while HTML an administrator placed in a page stays intact when an editor saves it; this covers the text, block Markdown fields, and raw front matter
- Markdown links with script addresses (`javascript:`) lose their address for everyone
- Admin actions with no explicit permission are now administrator-only instead of open to anyone who can edit content
- Users screens list all roles with descriptions; new users default to Editor, and an unknown or missing role can no longer turn into Admin
- Refused requests for forms are written to the activity log
